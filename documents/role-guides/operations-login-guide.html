Create a new case

Use this sequence for every first-time request.

  1. Open New Entry

    Leave Reference ID unchanged; it is generated only after a successful save.

  2. Enter the identifiers

    Add Request ID, client name, PAN, account type, channel, location, segment, RM, and CSE name.

  3. Record ownership and dates

    Choose who must act next, enter inward date, and add any process dates already known.

  4. Select the latest status

    Use the status that represents the event being recorded. Query, discrepancy, and returned-form statuses require event details.

  5. Save and retain the Reference ID

    The confirmation displays an ID such as MOFSL-YYYYMMDD-XXXXXXXX. Use it for every related entry.

Progress an existing case

Two legitimate pathsSelect Edit in Case Register to correct the selected entry, or create a Resubmission, Discrepancy Resolution, or Modification row using the same Reference ID when a new business event occurred.
  1. Find the case

    Search the Case Register by reference, client, or PAN.

  2. Confirm the latest journey

    Review status, stage, query count, hold days, RFT, net TAT, and Audit History.

  3. Record the next event

    Update status, dates, owner, query details, and remarks, then save.

Bulk upload

  • Download the CSV template from Bulk Upload.
  • Leave Reference ID blank for New entries; provide an existing ID for related entries.
  • Review the validation preview and correct invalid source rows.
  • Import valid rows and review any rows that could not be imported.

Important rules

  • Process dates are manual for Operations.
  • Physical submission requires the Physical channel.
  • Digital form sent requires the Digital channel.
  • Closed cases require account number and opening date.
  • User Administration is unavailable.

Avoid

  • Creating a second New case for a resubmission.
  • Changing a generated Reference ID.
  • Saving a query without useful details.
  • Skipping Audit History after corrections.
