# Frontend code walkthrough

## `frontend/index.html`

This file defines the page structure:

- Boot and login screens
- Sidebar navigation
- MIS overview and performance MIS
- Case register
- Case-entry form
- CSV upload and validation preview
- Audit history
- Admin user creation and user list

Role-sensitive elements use `data-admin`, `data-write`, or `data-bulk`. These are convenience controls only; backend authorization remains authoritative.

## `frontend/styles.css`

This contains all visual rules: responsive layout, navigation, cards, tables, status badges, forms, upload panels, and notifications. It has no business calculations.

## `frontend/app.ts`

### Types and state

`CaseRow`, `MisReport`, `Meta`, `ImportRow`, and `User` describe API data. Module-level state holds the current user, metadata, report, rows, history, CSV rows, editing ID, and selected MIS dimension.

### API and common helpers

- `api()` sends same-origin JSON requests and handles expired sessions.
- `escapeHtml()` protects HTML interpolation.
- `formatDate()` and `localToday()` format dates.
- `statusBadge()` selects visual status styling.
- `toast()` shows short notifications.

### Authentication and role UI

- `bootstrap()` restores an existing session.
- `login()` and `logout()` call authentication endpoints.
- `applyRoleUi()` hides unavailable navigation and constrains entry types.
- CSE status options and MOFSL status options are filtered in `populateMasters()`.

### Data loading and rendering

`loadAll()` concurrently loads metadata, reports, entries, and history. `renderAll()` delegates to focused render functions for KPIs, pipeline, quality, attention cases, grouped MIS, register, and audit history.

### Entry form

- `formPayload()` turns the form into a plain object.
- `validateFrontEnd()` mirrors important backend checks.
- `editCase()` either edits the exact entry for Admin/Operations or prepares a new related update for CSE/MOFSL.
- `saveForm()` validates, calls POST or PUT, reloads all data, and returns to the register.
- `applyAutomaticDates()` only acts for an Admin who selected the checkbox; the backend repeats this rule securely.

### CSV upload

- `parseCsvLine()` supports quoted CSV fields and escaped quotes.
- `parseCsv()` maps headers to application fields and validates each row.
- `previewImport()` shows valid/invalid rows.
- `importValid()` submits valid rows one at a time through the normal case API.

> [!note]
> CSV upload is not one atomic database transaction. A later row can fail after earlier rows have been saved.

### Browser initialization

The final block connects DOM events to functions, then calls `bootstrap()`. The browser executes `frontend/dist/app.js`, which is generated by TypeScript and must not be edited manually.
