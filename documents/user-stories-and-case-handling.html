Client onboarding flow

A business guide showing how a case moves from the first CSE request to account opening, including queries, resubmissions, holds, rejections, cancellations, and other exceptions.

One case, one continuous journey

Every onboarding case receives an automatically generated Reference ID when its New entry is saved. That same Reference ID must be used for all later resubmissions, discrepancy resolutions, and modifications. This keeps the complete journey together and ensures that turnaround time continues from the original inward date.

Stage-by-stage handling

1

CSE request to Operations

Receive the request and confirm whether enough information is available.

Normal path

  1. CSE sends the onboarding request.
  2. Record the inward date and case details.
  3. Set the status to Request Received from CSE.
  4. Operations checks the information and moves it to Under Review by Operations.
  5. If complete, proceed to form preparation.

If information is missing

Select Query Raised to CSE - Missing Information and describe exactly what is required.
  1. The case waits with CSE.
  2. When information returns, record a related resubmission.
  3. Select Resubmitted by CSE.
  4. Operations reviews it again.
Complete → Stage 2. Still incomplete → raise another clearly described query.
2

Form preparation and submission for signing

Prepare the application and follow the correct channel.

Preparation

  1. Select Application Form Under Preparation.
  2. Complete the application using the approved client information.
  3. Confirm whether the channel is Physical or Digital.

Channel decision

Physical: send the form to CSE and select Physical Form Submitted to CSE.

Digital: send the form to the client and select Digital Form Sent to Client.
Form sent for signing → wait for the signed form, then proceed to Stage 3.
3

Receipt and review of signed form

Check signatures, documents, and completeness.

Normal path

  1. When the signed form arrives, select Signed Form Received from CSE.
  2. Move to Under Review - Signed Form.
  3. Check signatures, supporting documents, and all mandatory details.
  4. If everything is correct, continue toward MOFSL readiness.

If a discrepancy is found

Use Discrepancy Raised to CSE when correction or information is required. Use Form Returned to CSE when the physical form itself is sent back.

Record clear details so CSE knows exactly what must be corrected. The case then moves through Stage 4 resolution.

No discrepancy → ready path. Discrepancy → Stage 4 resolution loop.
4

Discrepancy resolution or resubmission

Receive corrections and decide whether the form is now in order.

Receive the correction

  1. Use Discrepancy Resolution Received when CSE provides an answer or missing item.
  2. Use Resubmitted Form Received - Under Review when a corrected form is returned.
  3. Operations checks the correction against the original discrepancy.

Review outcome

Correct: select Form Found in Order - Ready for MOFSL Submission.

Still incorrect: return to the appropriate discrepancy status with fresh, specific details.
Found in order → Stage 5. Still pending → repeat the Stage 3–4 correction loop.
5

Submission to MOFSL

Send the approved case for account opening and resolve external queries.

Normal path

  1. Submit the complete case to MOFSL.
  2. Record the submission date.
  3. Select Submitted to MOFSL.
  4. Wait for account-opening confirmation.

If MOFSL raises a query

Select Query Raised by MOFSL and record the exact requirement.
  1. Obtain the correction or information.
  2. Send it back to MOFSL.
  3. Select Query Resolved - Resubmitted to MOFSL.
  4. If another query arrives, repeat the loop as a new query event.
Accepted by MOFSL → Stage 6.
6

Account opening and closure

Record the result and complete client communication.

Account opened

  1. Enter the account number.
  2. Enter the account opening date.
  3. Select Account Opened.
  4. Verify the opening date is not earlier than the original inward date.

Final communication

  1. Send the account-opening communication to the relevant person.
  2. Select Communication Sent - Case Closed.
  3. Add any final remarks needed for the record.
Case journey complete.

Edge-case handling

Generated Reference ID

A New case does not yet have a Reference ID

Leave the field unchanged and save the New entry. The Reference ID is generated automatically. Copy or select that generated ID whenever recording a Resubmission, Discrepancy Resolution, or Modification.

Unknown Reference ID

A resubmission arrives before the original case exists

First create the original case as New using its first inward date. Then add the resubmission under the same Reference ID.

Repeated Query

The first response is still incomplete

Complete the first response review, then raise a fresh query with updated details. Do not overwrite the earlier query; the history should show both rounds.

Two Open Queries

More than one issue is pending

Record each query separately and resolve them in the order their responses are received. Keep details specific enough to identify which issue is being closed.

Wrong Channel

Physical status selected for a digital case, or vice versa

Correct the Channel or select the correct submission status. Physical Form Submitted is only for Physical cases; Digital Form Sent is only for Digital cases.

Missing Query Details

A query/discrepancy status has no explanation

Add the exact missing document, mismatch, incomplete detail, or MOFSL requirement before saving. This gives the next owner an actionable instruction.

On Hold

The case pauses for a non-query reason

Select On Hold and explain the reason in remarks. Resume with the appropriate normal status when work restarts. On Hold does not itself represent a CSE/MOFSL query-resolution pair.

Rejected

The onboarding request cannot proceed

Select Rejected and record the reason in remarks. The case remains visible as an exception but is kept outside normal completed-case performance.

Cancelled

The client withdraws the request

Select Cancelled by Client and record when and why the cancellation was received. It remains visible as an exception rather than a successful closure.

Missing Closure Details

Account is opened but number or date is unavailable

Do not close the case yet. Obtain both the account number and account opening date, then record Account Opened.

Incorrect Date

Opening date is earlier than inward date

Verify both dates against source records and correct the mistaken value. Never change the original inward date merely to make the dates pass validation.

Modification

A completed or active case needs a later change

Use the same Reference ID and add a Modification entry. Explain what changed and select the status that accurately represents the current owner and stage.

Wrong CSE

A CSE cannot see or update the case

Confirm that CSE Name matches the assigned user's display name. Operations or Admin should correct the assignment when it was entered incorrectly.

MOFSL Too Early

MOFSL needs to act before submission

Operations must first complete readiness and record Submitted to MOFSL. MOFSL handling begins once the case reaches Stage 5.

Status Chosen by Mistake

An incorrect status was recorded

Correct it promptly using the appropriate permitted user and add a clear remark. Do not create a false query or resolution simply to move the case back.

Bulk Upload Partial Success

Some uploaded rows succeed and others fail

Record the generated Reference IDs for successful New rows. Correct and upload only the rejected rows so the successful cases are not created a second time.

Example journeys

Straight-through case

Right First Time

Request Received → Under Review → Form Preparation → Form Sent → Signed Form Received → Found in Order → Submitted to MOFSL → Account Opened → Closed

No qualifying query or discrepancy occurs, so the case remains RFT.

CSE query case

Missing information resolved

Request Received → Query to CSE → Resubmitted by CSE → Review → Continue normal journey

The waiting period ends on resubmission. The case is NRFT because a query occurred.

Signed-form discrepancy

Form corrected and returned

Signed Form Received → Discrepancy Raised / Form Returned → Corrected Form Received → Found in Order → MOFSL

The case may loop more than once until all discrepancies are resolved.

MOFSL query case

External query resolved

Submitted to MOFSL → Query Raised by MOFSL → Resolved and Resubmitted → Account Opened → Closed

The case is NRFT and the query waiting period is excluded from net turnaround time.

Operating discipline: Use the generated Reference ID for a New case, keep that same ID for the entire client journey, use the status that describes what actually happened, add clear details for every query or exception, and never reset the inward date when a case is resubmitted.
